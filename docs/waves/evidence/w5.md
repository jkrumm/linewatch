## The latency band (l3 × 5)

`latency-band-chart.tsx` is `CartesianChart` with consumer marks from `@tanstack/charts/{area,dot,line,rect,rule,mark/decorative}`;
the visx `Area`/`LinePath`/`Group`/`HatchPattern` imports and `@visx/shape` are gone.

| Mark | 2.x |
|-|-|
| median, overlay | `lineY` from `plot.rows(key)` (carries the cursor dot and the tooltip row) |
| worst-ping envelope | `lineY`, decorative, `strokeOpacity` 0.35 |
| p5–p95 | `areaY` `y1`/`y2`, decorative; a partly-null band edge is a null (a gap), never 0 |
| loss dots | `dot`, one decorative mark per threshold, each gated on its own legend entry |
| full-loss band | `rect` per bucket, opacity grouped in 5% steps (`rect` has one opacity per mark) |
| unmeasured | flat `ABSENT_COLOR` `rect` column + a new `Not measured` legend entry (1.x hatch had none) |
| outage rail + edges | `rect` 3 px rail + `ruleX` edges, clamped to the drawn grid, never skipped |
| vantage rail | two flat `rect` marks (`unknown` neutral, other non-`all` warn), 5 px |

`x` is `new Date(bucketStart)`; `Point.key` is deleted. `renderExtraTooltipRows` became
`extraTooltipRows: (bucket) => ChartTooltipRow[]`; `routes/index.tsx`'s stubbed `InternetFoldRows` is back as
`internetFoldRows` (`Folded from 3 of 3 anchors`, `Worst single anchor` only when it differs). Tooltip
rows are data; the `shape` of a swatch (bar/dot/line) is gone, only `solid`/`dashed` survives.

Browser check (24 h, live data, light and dark): all five instances (folded + router, then gateway /
Cloudflare / Google / Quad9) draw; envelope, band, loss dots and the trailing unmeasured column match
`v-dark-latency-internet.png` at the same window; no console message. Hovering one chart puts a
tooltip with a crosshair on the availability strip, the latency band and throughput at the same
column; the latency tooltip header `15. Okt., 02:50`, rows `Internet 5.0 ms · Router 0.9 ms · p5 – p95 ·
Worst ping · Loss · Worst cycle · Measured 10 of 10 expected cycles · Folded from 3 of 3 anchors ·
Vantage Home line`.

## `tooltip.follow: false` and `tooltip.label` — settled

- **`follow: false` is the 2.x default and not configurable, and that is enough.** `compile.js`
  `tooltipSpec` hard-wires `anchor: "group-center"`: the tooltip sits on the cursor's column, never on the
  pointer. The 1.x flag existed to opt out of pointer-following; there is nothing left to opt out of. What
  2.x lacks is only the *ability to choose*, which no consumer here needs. Row closed.
- **`tooltip.label` has no 2.x slot.** The badge (clock beside the date) is gone; the clock is folded into the header
  (`fmtDateTime`), which is where the strips already put it. What 2.x lacks: a place to name *what a
  chart is a strip of* (W4 friction 6). The latency band does not need it, its series are named.
- **Not provided, checked:** `getMarker` (the crosshair dot tracking the *worst* cycle's colour) is not drawn by
  the `CartesianChart` rung when `marks` are consumer-supplied; the cursor dot is the series colour, so the
  dot no longer takes the loss colour of the hovered bucket. The tooltip's `Worst cycle` row still says it.
